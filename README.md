# mail-assistant-webapp

Next.js frontend for the AI Mail Assistant. The backend is
[mail-assistant-server](https://github.com/pojesh/mail-assistant-server); the shared spec is in
[`docs/implementation.md`](docs/implementation.md).

> The app never sends email. Replies are saved as Gmail drafts, and every write waits in Approvals.

**API contract:** `openapi.json` here was copied from the server's `openapi.json`
(server working tree, unreleased; tag releases `server-vX.Y.Z` and record the version here).

## Stack

Next.js 16 (App Router, TypeScript strict, `output: "standalone"`), Tailwind CSS v4, shadcn/ui
(Radix), TanStack Query, `openapi-fetch` with types generated by `openapi-typescript`, motion,
next-themes, sonner, cmdk, DOMPurify. Font: Inter. Accent: indigo.

## How it talks to the server

- The browser only calls this origin. `src/app/api/[...path]/route.ts` proxies every `/api/*`
  request to `API_URL` **at request time**, forwarding cookies and streaming bodies (chat SSE).
  So the session cookie is first-party and the server URL is never baked into the build.
- `src/lib/api/client.ts` is the single typed client: paths and response types come from the
  generated `src/lib/api/schema.d.ts` (never hand-written). It adds the CSRF header to
  state-changing requests and turns error responses into `ApiError` with the server's message.
- Sign-in is a full-page link to `/api/auth/google/login`; Google redirects back to
  `/api/auth/google/callback`, which the proxy forwards to the server.

## Local development

```bash
pnpm install
cp .env.example .env.local        # API_URL=http://localhost:8000
pnpm gen:api                      # copy ../mail-assistant-server/openapi.json and generate types
pnpm dev                          # http://localhost:3000 (run the server on :8000 first)
```

Re-run `pnpm gen:api` whenever the server's `openapi.json` changes. `OPENAPI_SOURCE` can point at
another path or a URL.

| Script                                         | What it does                                            |
| ---------------------------------------------- | ------------------------------------------------------- |
| `pnpm dev` / `pnpm build` / `pnpm start`       | Next.js dev server / production build / serve the build |
| `pnpm lint` / `pnpm typecheck` / `pnpm format` | ESLint / `tsc --noEmit` / Prettier                      |
| `pnpm gen:api`                                 | refresh `openapi.json` and `src/lib/api/schema.d.ts`    |
| `pnpm test:e2e`                                | Playwright end-to-end + accessibility tests (see below) |

## Structure

```
src/app/(marketing)/page.tsx     landing + "Continue with Google"
src/app/(app)/layout.tsx         signed-in shell (auth guard, sidebar, top bar, banners)
src/app/(app)/inbox/…            three-pane inbox: list (layout) + email detail ([id])
src/app/(app)/{approvals,calendar,chat,files,activity,preferences,settings}/
src/app/onboarding/              first-run wizard
src/app/api/[...path]/route.ts   runtime proxy to API_URL
src/components/shell/            sidebar, top bar, bell, command palette, shortcuts, phone nav
src/components/inbox/            list, rows, filters, detail, sanitised body, AI panel, overview strip
src/components/chat/             chat page + slide-over panel (streamed answers with citations)
src/components/approvals/        draft / scheduling approval cards
src/components/{calendar,files,activity,settings,preferences,onboarding}/
src/lib/                         API client, SSE reader, query keys, formatting, categories, nav
e2e/                             Playwright tests and the typed mock API
```

## Pages

| Page        | What it shows                                                                                                                                    |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Inbox       | Overview strip (digest headline, counts, 7-day mood), filters, AI-triaged list, email with summary and actions                                   |
| Approvals   | Draft replies (pick a variant, edit, approve) and meeting proposals; pending / approved / rejected                                               |
| Calendar    | Week view with automatically added events (undo within the window) and proposals                                                                 |
| Chat        | Ask questions about your mail; answers stream with the steps taken and links to the source threads. Also a slide-over panel from any page (`⌘J`) |
| Files       | Every attachment, searchable and filterable by type                                                                                              |
| Activity    | Everything the assistant did, with undo where possible                                                                                           |
| Preferences | Working hours, VIPs, focus time, autonomy limits, notes                                                                                          |
| Settings    | Account, Google connection, theme, delete all data                                                                                               |

## UI principles

Calm and fast: neutral surfaces with one indigo accent, light/dark/system themes, 150–250 ms
transitions (motion), and `prefers-reduced-motion` respected. Every chip has an icon and text
(colour is never the only signal), icon buttons have labels, focus rings are visible, and the
layout goes from three panes on desktop to list → detail with a bottom bar on phones. Email HTML
is sanitised with DOMPurify and shown in a sandboxed iframe with a strict CSP; remote images are
blocked until you choose "Show images".

Keyboard (press `?` in the app for the list; `⌘` is `Ctrl` on Windows/Linux):

| Keys                                 | Action                                                        |
| ------------------------------------ | ------------------------------------------------------------- |
| `⌘K` / `⌘J`                          | Command palette / chat panel                                  |
| `J` / `K`                            | Next / previous email                                         |
| `D` / `T`                            | Draft a reply / find a time for the open email                |
| `A`                                  | Approvals                                                     |
| `G` then `I` `C` `H` `F` `P` `Y` `S` | Inbox, Calendar, Chat, Files, Preferences, Activity, Settings |

## End-to-end tests

```bash
pnpm exec playwright install chromium   # once
pnpm test:e2e
```

Playwright builds the app and serves it on port 3100. Every `/api/*` call is answered in the
browser by `e2e/mock-api.ts` (fixtures typed from the generated schema, unmocked paths fail with
500), so no server, Google account or LLM is needed. `API_URL` points at a dead port so nothing
can leak to a real backend. Covered: landing and sign-in redirect, inbox and email detail,
approving an edited draft, undoing an automatic event, chat streaming with citations, keyboard
shortcuts, the phone layout (Pixel 7), and an axe WCAG 2 A/AA scan of the main pages (fails on
serious or critical issues).

## Evaluation page

`/eval` (no sign-in) shows the latest scenario evaluation from the server repo: quality targets,
latency, and every case with details (chat answers, tools used, retrieval and judged claims). It
reads `../mail-assistant-server/tests/scenarios/results/latest.json` on each request; set
`EVAL_RESULTS_PATH` to read another file. Produce results with `uv run pytest tests/scenarios`
in the server folder.

## Deployment

Cloud Run service `web`, continuously deployed from `main` with the `Dockerfile` (standalone
server on `$PORT`, non-root). Set `API_URL` to the `api` service URL. See the server repo's
`infra/README.md` for the full setup. CI (pull requests) runs lint, type-check, the API contract
check against the server repo, a production build and the Playwright tests.
